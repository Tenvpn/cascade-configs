# 3. Каскад по IPv6

Обычно банят IPv4 выхода, а его IPv6 продолжает жить. Телефону IPv6 не нужен: он ходит на мост по IPv4,
а мост стучится к выходу по IPv6.

```
телефон ──IPv4──► мост ──IPv6──► выход (IPv4 в бане — неважно)
```

## Условие

IPv6 должен быть **у обоих**: и у моста, и у выхода. Проверка на каждом сервере:

```
ip -6 addr show scope global      # есть ли глобальный IPv6
curl -6 -s https://ifconfig.co    # выходит ли он в интернет
```

И с моста до выхода: `ping -6 <EXIT_IPV6>`.

## Шаги

1. **Выход:** подключение должно слушать и IPv6. В 3X-UI поле «Listen IP» оставь пустым.
   В голом Xray — `"listen": "::"`, см. `exit-inbound-dualstack.json`.
2. **Мост:** в исходящем `to-exit` замени адрес `<EXIT_IP>` на `<EXIT_IPV6>`. Готовый вариант —
   `bridge-outbound-ipv6.json`: адрес IPv6 пишется без квадратных скобок.
3. Перезапустить Xray на мосте. Всё остальное, включая телефоны, не меняется.

## Если у моста нет IPv6

Бери другой мост, у которого он есть, или туннельный брокер (например, Hurricane Electric tunnelbroker).
Через брокер добавляется лишний прыжок и пинг.
