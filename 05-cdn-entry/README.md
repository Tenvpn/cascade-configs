# 5. Вход через CDN (XHTTP) для белых списков

В белых списках телефон пускают только к разрешённым адресам. Адреса сетей доставки (CDN) крупных компаний
в списке есть, поэтому первым звеном ставим CDN. Он принимает соединение и отдаёт его на твой мост
как обычные запросы к сайту.

```
телефон ──HTTPS (XHTTP)──► CDN ──HTTPS──► мост (origin) ──VLESS Reality──► выход
```

## Файлы

| Файл | Что |
|---|---|
| `bridge-inbound-xhttp.json` | входящее VLESS + XHTTP + TLS на мосте (origin для CDN) |
| `bridge-full.json` | мост целиком: вход из CDN → РФ напрямую → остальное на выход |

## Шаги

1. Домен `cdn.<YOUR_DOMAIN>` заводишь в CDN, источником (origin) указываешь `<BRIDGE_IP>:443` по HTTPS.
2. На мосте — настоящий сертификат на `cdn.<YOUR_DOMAIN>` (certbot / acme.sh) по путям из JSON.
3. Входящее из `bridge-inbound-xhttp.json`: путь `/<SECRET_PATH>` — длинный и случайный, `mode: auto`.
4. Исходящее на выход и маршрутизация — как в [схеме 2](../02-chain-3x-ui).
5. Ссылка для телефона:
   ```
   vless://<UUID_PHONE>@cdn.<YOUR_DOMAIN>:443?type=xhttp&security=tls&sni=cdn.<YOUR_DOMAIN>&host=cdn.<YOUR_DOMAIN>&path=%2F<SECRET_PATH>&mode=auto&fp=firefox#CDN
   ```

## Подводные камни

- **Трафик через CDN платный**, а бесплатные лимиты маленькие (десятки гигабайт). Посчитай заранее.
- **Ссылку на подписку за CDN не прячь.** Часть CDN теряет заголовки, и клиент не может добавить подписку.
- **Не добавляй `uplinkChunkSize` и другие тонкие поля XHTTP.** Тип некоторых полей менялся между версиями Xray,
  и клиент со старым ядром не разберёт весь конфиг.
- Такие входы закрывают быстрее остальных. Держи запасной.
